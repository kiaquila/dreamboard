# Plan 026: Горы hero как точки-данные

## Approach

Один PR. Извлечение делается офлайн скриптом из исходного PNG, в браузер
уходит только список точек. Рендер, спрайты и анимация из spec 014
остаются, меняется только источник поля точек.

## Extraction

Решётка исходника квадратная с шагом ~9.75 px, плюс точка в центре каждой
ячейки: ближайший сосед на расстоянии ~6.9 px. Прототип с квадратным окном
подавления 9x9 терял эти центральные точки, соседние точки смещались.

1. Темнота пикселя `D = 1 - luma`, два прохода размытия 3x3 (крупные точки
   дают один максимум).
2. Кандидаты: локальные максимумы размытой темноты не ниже 0.08 в круге
   радиуса `0.4 * pitch` (внутри расстояния до центральной точки).
3. Насыщенность точки: максимум сырой темноты в 3x3 вокруг кандидата,
   `ink = (peak - 0.06) / (0.91 - 0.06)`.
4. Каждый тёмный пиксель относится к ближайшему кандидату в пределах
   `0.75 * pitch` (Voronoi). Покрытие пикселя `(D - 0.06) / (peak - 0.06)`,
   площадь точки = сумма покрытий, центр = взвешенный центроид.
5. `ink` квантуется в 16 уровней (альфа `(a + 1) / 16`), радиус
   пересчитывается так, чтобы `alpha * pi * r^2` сохранил тон.
6. Сортировка по строке решётки (строки через полшага), затем по x.
7. Формат: `{"w","h","pitch","n","x":[],"y":[],"r":[],"a":[]}`,
   `x`, `y` в 1/8 px, `r` в 1/16 px, `a` 0..15.
8. Проверка: квантованные точки рисуются с 4x4 суперсэмплингом на
   разрешении исходника, оба изображения размываются окном в один шаг.
   MAE тона в области с тоном (размытый тон исходника > 0.05) должна быть
   не больше 0.03, иначе файл не пишется. MAE по всему кадру печатается
   для справки.

Результат: 14 651 точка, MAE 0.0097 в области с тоном и 0.0047 по кадру,
JSON 233 KB, gzip 63 KB (старый JPEG был 267 KB). Слипшиеся точки тёмного
переднего плана получают приблизительный радиус по суммарной площади.

## Rendering

`decodeHeroDots(json)` один раз проверяет форму ассета и переводит целые
в пиксели исходника. `buildField(asset, width, height)`:

- `scale = max(width / w, height * 0.62 / h)`, картинка по центру по x и
  прижата к низу;
- точки за краем canvas отбрасываются;
- экранный шаг `pitch * scale`; если он меньше 4 px, точки сливаются 4 в 1
  в квадратные ячейки `pitch * sqrt(2)`: центр взвешен по тону, альфа
  максимальная, радиус сохраняет суммарный тон;
- skyline: первая ячейка колонки шириной в один шаг с суммарным тоном
  `sum(alpha * pi * r^2) / spacing^2 > 0.077`; колонка берёт самый высокий
  skyline из себя и двух соседей, иначе бледный дальний хребет под порогом
  даёт вертикальный подтёк. depth и `snowcapTiming` как раньше, jitter
  хэшируется по экранным координатам;
- точки упорядочены по моменту оседания.

Для 390x844 шаг 5.4 px, для 844x390 4.9 px, для 1440x900 8.4 px:
прореживание не включается. Включается на 667x375 и 320x568.

Кадр. Осевшие точки один раз запекаются в offscreen-слой, кадр рисует
слой и только летящие точки (пик ~5.9k из 14.6k против 7.6k на кадр
раньше). Холст слоя создаётся только когда осела первая точка, финальный
кадр рисуется без слоя: секция в ожидании (прогресс 0) и готовая картинка
копию не держат. Замер на software canvas
1440x900@2: без слоя p50 24 мс, со слоем p50 15.6 мс и p95 22 мс, старая
реализация на 7.6k точек p50 12.7 мс и p95 22.5 мс.

## Delivery

JSON сжимается транспортом. Vercel и Cloudflare сжимают JSON сами. На
`cz` включён `gzip_types` для JSON в `deploy/cz/nginx.conf`, конфиг
нужно переустановить на хосте вручную.

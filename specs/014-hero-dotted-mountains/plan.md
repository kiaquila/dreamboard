# Plan 014: Точечные горы в hero и футер в стиле Ember

## Approach

Один PR, три логических коммита: спека и документация, графика и модуль
гор, футер. Тон берётся из готовой картинки, а не рисуется процедурно:
так сохраняются планы глубины и тени оригинала, а код остаётся небольшим.

## Design

Сэмплинг. Картинка рисуется в служебный canvas размером с секцию так,
чтобы закрыть всю ширину (на узких экранах не меньше 62% высоты) и быть
прижатой к низу. Для каждой ячейки сетки берётся средняя яркость пикселей,
темнота `dk = (0.952 - L) / (0.952 - 0.09)`. Ячейки светлее порога 0.035
пропускаются (небо). Радиус точки `r = (шаг / 2) * dk^0.55`, прозрачность
1 при `dk > 0.3`, иначе 0.55..1 (дальние хребты мягче).

Сборка "снег на вершины". Для каждой колонки известна первая тёмная
ячейка (линия хребта). Глубина точки `depth` = расстояние под хребтом,
нормированное на высоту горной зоны. Задержка `min(depth * 1.35, 0.68) +
jitter * 0.1`, длительность 0.22 от таймлайна 2.6 с (самые глубокие точки
заканчивают ровно на 1.0), easing outCubic,
подъём на 6 px и рост радиуса из нуля.

Отрисовка. Точки группируются по 12 уровням прозрачности и рисуются
кэшированными спрайтами кружков (шаг радиуса 0.25 px), а не `arc()` на
каждую точку: на 1440x900 около 7.6 тысяч точек за кадр.

Триггер. IntersectionObserver на обоих hero-слайдах: слайд 1 собирается
при загрузке, слайд 4 при докрутке; возврат из редактора снова показывает
сборку. При `prefers-reduced-motion: reduce` сразу финальный кадр.

Футер. Позиционирование и высота 45px остаются (от них зависит раскладка
слайдов), меняется только вид: прозрачный фон, DM Sans 12px, letter-spacing
0.06em, цвет `#8a877f`, ссылка `#1b1b1b` с линией `rgba(27,27,27,.18)` и
hover `#b07f2f`.

## Asset generation

Локально на macOS из исходника 1672x941:

```sh
sips -s format jpeg -s formatOptions 72 -Z 1200 source.png \
  --out src/assets/images/landing/hero-mountains-halftone.jpg
```

Картинка нужна только как источник тона, поэтому 1200px и качество 72
достаточно (267 КБ).
